CS-Viewer

4台のノードが送り合う電波の強さから、熊が通った区間を見つけるシステムの記録を確かめるサイトです。地上局が保存したCSVを読み込むだけで、グラフの表示、データの分離、過去の版の確認ができます。

はじめての方へ

4つの機能

目的に合わせて選んでください。上のメニューからいつでも切り替えられます。

互換性

ノード・地上局・CS-Viewer のどの版どうしが一緒に使えるかをまとめました。表の版や記号を押すと、関係する所が光り、理由が下に出ます。

今の版（自由通信方式：ノード v2.0・地上局 v2.0、CS-Viewer v4.4）で、データがどう流れるかの図です。

  • ノード v2.0・地上局 v2.0 では、地上局のコマンドで進めます（s：スタート → a：GW 指名 → t：記録試験 → b：記録開始 → e：記録終了。地上局モニターのボタンか、Thonny で打って y）。ノードは電源を入れても何も送らず、記録試験と記録のあいだだけ BEACON を0.05秒ごとに出します。
  • 記録中は、各ノードも自分が測った3つを A_000.csv などに保存します（時刻0は記録開始を受けた瞬間）。CS-Viewer のグラフ生成で A〜D をまとめて読み込むと、12方向のグラフになります。
  • 地上局は GW を通ったパケットだけを保存します（ほかのノードから直接届いた電波は、GW の選定にだけ使います）。
  • GW は自分のパケットを地上局あてには送り直さず、地上局は GW が全員へ送った1通をそのまま受けます（ノード v1.0・地上局 v1.4 から。それより前は2通届き、1件として保存していました）。
  • パケットは小さくしてあります（ノード v1.0・地上局 v1.4 から）。BEACON は4バイト（送ったノードと GW の印の1バイト＋強さ3つ）、START・RESET・ASSIGN は1バイトで、種類は送り主と長さで見分けます。
  • BEACON の最後の「GW の印」で、地上局の電波が届かないノードも GW を知り、時刻合わせができます。
  • 通過の判定は地上局がします（ノード v0.9・地上局 v1.3 から）。地上局は0.1秒ごとに、GW 経由で届いた最新の12個の値で6区間を往復2方向ずつ判定し、検知した区間を5秒間「害獣を検知」と表示して、r で作る GS_000_PASS.csv に1回1行で保存します。CS-Viewer のグラフでは、同じ番号の GS_000.csv に赤い縦の線で重ねて見られます。

今の版（指定通信方式：ノード v0.2・地上局 v0.2、CS-Viewer v4.4）で、データがどう流れるかの図です。

  • GW が決まるまでは、各ノードは存在通知（100ms ごと）だけを送り、ノードどうしの通信はしません。地上局は g で5秒間計測して GW を選びます。
  • 地上局は GW を通ったパケットだけを保存します（ほかのノードから直接届いた電波は、g の計測にだけ使います）。GW 自身のパケットは2通届きますが、1件として保存します。
  • 地上局の電波が届かないノードも、GW のサイクル開始を受け取って GW を知り、参加できます。

ノード（行）と地上局（列）の組み合わせです。4台のノードは必ず同じ版にしてください。

はじめての方へ

実験のデータをグラフで見るまでの流れです。

  1. CSVをPCへ移す地上局のmicroSDカードにある GS_000.csv などのファイルを、PCにコピーします。
  2. グラフ生成を開く上のメニューの「グラフ生成」を押し、CSVを枠の中にドラッグ＆ドロップします。複数まとめて読め、グラフ用と全記録は自動で振り分けます。

使い方（操作と表示の説明）

「動画（6区間）」では、地上局モニターの6区間のグラフ（記録中の表示）と同じ絵を、読み込んだファイルから作り直して動画にします。0.1秒ごとに、その時点までに届いた最新の値（1秒より古い値は 0 = 未受信）で1行を作り、モニターと同じく直近の秒数を流して描きます（青が前の文字から後の文字へ、緑が逆向き、黄色の破線が −90 dBm、下の赤い帯が未受信）。同じ番号の GS_000_PASS.csv を一緒に読み込んでいると、検知の時刻から5秒間、その区間のグラフの枠と背景が赤くなり、見出しに「害獣を検知」と最後の検知の時刻（記録の経過時間）が出ます。上の「動画の大きさ」「横軸」「縦軸」「並べ方」で動画の寸法と縮尺を変えられます（縦軸は空欄なら自動。文字や線の太さは大きさに合わせて変わります）。「動画を保存」は、選んだ速さで最初から最後まで再生しながら録画し、MP4（使えないブラウザでは WebM）で保存します。保存には「動画の長さ ÷ 速さ」と同じだけ時間がかかり、そのあいだはこのタブでこの画面を表示したままにしてください（ほかのタブやページに移ると一時停止し、戻ると続きから録画します）。

比較表示では、選んだ行を横軸をそろえて縦に並べます。横軸は上の「区間・横軸」で全行共通です。縦軸は、上の「縦軸」が空欄なら行ごとに区間内の最小値−2〜最大値+2 dBm（0 は受信なしとして除き、線も切ります）。上の「縦軸」に入れると全行に、グラフの下の「行ごとの縦軸」に入れるとその行だけに効きます（行ごとの欄を空にすると元に戻ります）。ドラッグで拡大すると全行の横軸がそろって拡大され、ダブルクリックで戻ります。右上の小さなボタンで大きさ（横幅の小・中・大）と背景（黒・白）を切り替えます。縦横比は「横:縦」の欄に数字を入れて変えられます（初めは 3:2。高さは横幅×縦÷横で、120〜3600px）。画像としてコピー・PNG保存でき、画像も同じ縦横比です（表示の2倍の解像度）。

上の操作パネルは、右上の「たたむ」で今の設定を並べた1行の要約になり、「ひらく」で元に戻ります。ドラッグで拡大、ダブルクリックで元に戻す。凡例をクリックすると線の表示・非表示を切り替えます。グラフの下の値をクリックすると、その高さに線を引きます（複数可、もう一度押すと消えます）。

「区間・横軸」の秒数は、統計の範囲とグラフの横軸の表示範囲を兼ねます。「縦軸」には dBm の下限と上限を入れます。上の欄は全部のグラフに、各グラフの下の欄はそのグラフだけに効きます。上の欄に入れた値はファイルやグラフの分け方を切り替えても保たれるので、同じ目盛りで見比べられます（臙脂色の枠が指定中の印で、「自動に戻す」で解除）。ドラッグでの拡大は一時的で、ダブルクリックすると指定した範囲に戻ります。

「通過検知（試験的）」をオンにすると、「ペア別（6）」の各グラフ（比較表示でないとき）に、方向ごとの基準値（直前 x 秒の平均）を破線、「基準値 − 下側の閾値」と「基準値 + 上側の閾値」を点線で、その方向の線と同じ色で重ね、反応ありの点を ○ で示します。基準値の線は、その方向で最初に受信してから x 秒たった点から出ます。区間として検知した通過（最初に検知した時刻から、その y 秒間で最後に検知した点まで）は黄色の帯、入れた通過時刻は紫の縦の点線、その前後 W 秒は紫の薄い帯です。グラフの右上には今の設定が出るので、スクリーンショットだけで条件が分かります。マウスを乗せると、その時点の基準値（反応ありの点では「反応あり」も）が出ます。凡例や線の選択で方向を消すと、その方向の線と印も消えます（区間の判定には使います）。計算では、同じ time_s の行が複数あるときは最後の行だけを使い、0 と空欄（未受信）は使いません。「区間・横軸」の範囲には影響されず、常にファイル全体を使います。

速さ

地上局の検知

地上局 v1.3 以降が r のたびに保存する通過の記録（GS_000_PASS.csv）を、同じ番号の GS_000.csv のグラフに赤い縦の線で重ねています（ペア別はその区間、測定ノード別はそのノードを含む区間、全体はすべての区間、比較表示も同じ）。線の上の区間名にマウスを乗せると、2方向の値・基準値・反応が出ます。時刻を押すと、その前後5秒に全部のグラフを拡大します（ダブルクリックで元に戻ります。「動画（6区間）」のときは、動画をその時刻へ移します）。上の「地上局の検知」のボタンで線を消せます。

通過検知（試験的）

読み込んだすべてのファイルについて、ファイル全体で計算しています（「区間・横軸」の範囲には影響されません）。

基準値・閾値の線と検知の帯は、「ペア別（6）」のグラフ（比較表示でないとき）に重ねて表示します。

通過時刻の評価前後 W秒

ファイルごとに、通過した時刻 [s] をカンマか空白で区切って入れます（例：21.69, 56.55）。通過の前後 W 秒に検知（開始〜終了）が少しでもかかれば、その通過は「検出」です。どの通過の前後 W 秒にもかからない検知は「誤検知」です。データのある区間がいくつあっても、そのファイルのすべての区間の検知をまとめて数えます。通過時刻を入れていないファイルは評価せず、合計にも含めません。

基準値

検知の一覧

区間の2方向の反応を判定ルールで合わせ、最初に検知した時刻から y 秒間（y 秒ちょうどの点は含めない）を1回の通過としています。y 秒たった時点でまだ検知していれば、そこから次の通過です。開始は最初に検知した時刻、終了はその y 秒間で最後に検知した点の時刻、長さは終了 − 開始です（1点だけなら 0.0 秒で、グラフでは細い帯になります）。

区間ごとの電波強度

各ノードが測った3区間の強さです（BEACON の中身）。届いたパケットを1つずつ、ミリ秒単位の時刻で並べています。点線は GW が切り替わった時刻です。ドラッグで拡大すると、このページのグラフがすべて同じ範囲になります（ダブルクリックで元に戻す）。

各ノードが測った3区間の強さです（報告パケットの中身）。各値を、地上局がサイクル開始を受け取った時刻に「連番×間隔＋送ったノードのずらし」を足した時刻に並べています。受け取れなかった値（0）のところは線を切ります。点線は GW が切り替わった時刻です。ドラッグで拡大すると、このページのグラフがすべて同じ範囲になります（ダブルクリックで元に戻す）。

グラフの部品を読み込めませんでした（インターネット接続を確かめてください）。集計と一覧はそのまま使えます。

取りこぼしの集計

各ノードの BEACON には1ずつ増える番号（seq）が入っています。番号が飛んだところを、地上局まで届かなかったパケットとして数えます。時刻合わせで番号が0に戻ったところは、戻った後の抜けだけを数えます。地上局 v1.4 の全記録には番号がないので、地上局が受けた時刻の間隔から数えます（0.1秒ごとに届くはずなので、間隔を0.1秒で割って四捨五入した数 − 1。ノードが再起動していた間も取りこぼしに数えます）。地上局 v2.0 の新しい流れ（記録開始などのコマンドの行がある記録）は、BEACON が0.05秒ごとなので、間隔を0.05秒で割って数えます。

指定通信方式では、サイクル番号ごとに各ノードが送るはずの検出用パケット（初期設定は8回）と報告パケット（1回）のうち、地上局の記録にないものを数えます。ノードがサイクル開始を受け取れずに送らなかった分も、取りこぼしに含まれます。

取りこぼしはありません。

地上局モニター

地上局を USB で PC につなぎ、手順に沿ったコマンドの送信と、通過の区間ごとの表示と、Thonny と同じシェル・プロッターを1つの画面で使います。

使い方
  1. Thonny を閉じます。Thonny と同時には使えません。
  2. 地上局を USB で PC につなぎ、パソコンの Chrome か Edge でこのページを開きます。
  3. 「接続」を押し、出てきた一覧から地上局のポートを選びます。
  4. 地上局 v2.0 のとき：左の「コマンド」を上から順に使います（1 s：スタート → 2 a：GW 指名 → 3 t：記録試験 → 4 b：記録開始 → 5 e：記録終了）。地上局の状態に合うボタンだけ押せます（押せないボタンに重ねると理由が出ます）。ボタンを押すと確認の窓が出て、「はい」で地上局にキーと y を送ります。
  5. 地上局 v1.4 以前のとき：「g：GW を選ぶ」で GW を選び、GW が決まったら「r：記録を始める」で時刻をそろえて microSD への保存を始めます。シェルの入力欄に g・r を打って Enter を押しても同じです。
  6. 地上局のプログラムが止まっているときは「地上局を再起動」を押します。保存中のファイルは閉じられ、GW の選び直し（g）が必要になります。

接続すると、地上局に v を送って版を確かめます。コマンド（s・a・t・b・e）は地上局 v2.0 のときだけ押せます。それ以外の版では警告を出し、コマンドのボタンを押せなくします（g・r・再起動・シェル・プロッター・区間の表示は今までどおり使えます）。GW の選定中は、a の上の小さな表に、直前5秒に地上局へ届いた選定パケットの件数と平均を出し、推薦されたノードに印を付けます。推薦以外のノードも選んで指名できます。右の6区間のグラフ（往復2本、−90 dBm の点線、未受信のときは赤い帯）は、記録試験（t）のときは13秒分、記録中は直近の30秒を流して描き、終わったあとは最後の絵を残します。記録試験が終わると、グラフの下に方向ごとの最小・平均・届いた割合の表が出ます（赤：一度も届かなかった、黄：−90 dBm 未満になったことがある）。表は記録開始（b）かスタート（s）を送ると消えます。記録中は、上の帯に「● 記録中」と経過時間、地上局のファイル名を出します。判断はいつも人が行います。

区間の状態（―・害獣を検知）は、右の6区間のグラフの見出しに出し、地上局がその区間を「害獣を検知」と出しているあいだ、グラフの枠と背景を赤くします（v4.3 から。v4.2 まではグラフの下のタイルで表示していました）。見出しには最後に検知した時刻（PC の時計）も出します。地上局 v1.4 以前のときも、グラフの線は描きませんが、枠は同じように光ります。区間の表示は地上局 v1.1 以降で出ます。6区間（A-B・A-C・A-D・B-C・B-D・C-D）すべての状態を出すのは v1.2 以降で、v1.1 は A-C・B-D を出さないので、その2つは「地上局が出していません」と薄く表示します（v1.1 の D-A は A-D に出ます）。v1.3 以降は、地上局が GW 経由の値から自分で通過を判定します（ノード v0.9 は通過速報を送りません）。シェルとプロッターは地上局 v1.0 でも使えます。区間の表示と検知の履歴は、地上局が出す行をもとにしています。g の計測中と GW が決まった直後の5秒間は地上局が区間の表示を止めるので、このページの区間の状態も「表示なし」になります。検知の履歴はページを閉じると消えるので、必要なら CSV で保存してください。

シェルには、地上局が出した行をそのまま直近2000行まで表示します。入力欄で ↑・↓ を押すと、前に送った文字を呼び出せます。プロッターは Thonny と同じく、シェルのいちばん下に見えている行までの31行から数値を描きます。シェルをさかのぼると、プロッターもその位置を描きます。プロッターをクリックすると縦軸を合わせ直します。区間の状態の文字（｜A-B ― など）はプロッターでは使わないので、地上局 v1.0 と同じ絵になります。

このブラウザでは USB の接続（Web Serial）が使えません。パソコンの Chrome か Edge で開いてください。

      MACアドレス

      このシステムで使うマイコンのMACアドレス帳です。最新のMACアドレスはここで管理します。

      MACアドレスとは

      ネットワークにつながる機器が1台ずつ持っている、住所のような番号です。80:f1:b2:64:2f:d4 のように、2けたの英数字（16進数）6組をコロン（:）でつないで書きます。

      ノードどうしの通信（ESP-NOW）では、この番号で「どの機体から届いた電波か」を見分けます。プログラムに書いた番号が1文字でも違うと、その機体の電波は無視されてしまいます。

      ESP32 には「Wi-Fi STA 用」と「SoftAP 用」の2つのMACアドレスがあります。このシステムで使うのは STA 用です（SoftAP 用は最後の数字が1だけ大きいので、取り違えに注意してください）。

      使い方

      1. MACアドレスを調べる新しいマイコンを Thonny につなぎ、次のプログラムを実行すると、シェルにMACアドレスが表示されます。 
        import network, binascii
sta = network.WLAN(network.STA_IF)
sta.active(True)
sta.disconnect()
print(binascii.hexlify(sta.config('mac'), ':').decode())
      2. 表に登録する下の「編集する」を押して行を追加・変更し、「変更を保存」を押します。保存されたファイルを GitHub に push すると、全員の画面に反映されます。
      3. プログラムに書き込むいちばん下の「プログラム用のコピー」で、ノードA〜Dと地上局に使う機体を選び、できた文をコピーして main.py（4台とも同じ）と gs_main.py の MACS の部分に貼り付けます。NODE_ID は機体ごとに変えます。

      MACアドレス帳

      変更を入れたファイル（）を保存しました。
      1. 保存したファイルで、GitHub の cs-viewer にある同じ名前のファイルを置き換えて push します（Claude に頼む場合は「MACアドレスを変えたファイルを push して」と伝えてください）。
